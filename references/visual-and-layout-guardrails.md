# 视觉亮度、纵向五区排版与工程红线规范

本规范沉淀自 5 部 60 秒 `1080×1440 @ 60fps` 发光线描科普成片实测经验，作为制作阶段与代码修复的硬性参考。

---

## 1. 亮度指纹与辉光黄金参数

上游默认 `Kit()` 模版设置 `bloom: 0.9`、`K.fog` 较高且环境 `haze` 偏浓；在拥有大面积发光线描主角时，极易导致高亮像素超过 `3.5%`、背景泛灰。实测稳定命中 `qa_video.py` 绿区指标的参数组合如下：

| 参数 / 指标 | 黄金推荐区间 | 异常表现 | 修复手法 |
| :--- | :--- | :--- | :--- |
| **`Kit({ bloom })`** | `0.20 – 0.28`（封面单帧可放宽至 `0.60–0.85`） | `> 0.45` 易触发全片 `bright > 3.5%` | 降至 `0.22–0.28`，局部发光靠 `K.sprC` / `K.core` |
| **`Kit({ vignette })`** | `0.56 – 0.62` | `<= 0.40` 导致边角发灰、均亮超 `24` | 收紧至 `0.58–0.62`，稳固“暗底亮主体”反差 |
| **`K.fog(t, col, a)`** | `0.024 – 0.028` | `>= 0.06` 令全屏均值飙升 | 压低至 `0.025` 左右，仅作背景极微弱染色 |
| **`K.amb.keys` `haze`** | `0.04 – 0.12` | `> 0.20` 造成雾气糊屏 | 叙事低谷降到 `0.04–0.06`，高潮控制在 `0.10–0.12` |
| **30fps 草稿 `p99`** | **`>= 133`**（母带 `60fps --blur 2` 下限 `>= 130`） | 草稿 `130–131` 运动模糊后易掉破 `130` | 强化主角 `K.core` 亮核或主轮廓双层高光线 |
| **高亮像素 (`>110`)** | **`1.8% – 3.3%`**（硬红线 `<= 3.5%`） | `> 3.5%` 被判过亮过曝 | 收窄体光柱、`drawSoftBeam` 与 `bloom` |
| **画面均值 / 近黑帧** | `mean 17 – 20` / `near_black 17% – 39%` | `<14` 过暗或 `>24` 过亮 | 在反转困境段落（Breakdown）刻意收光留呼吸 |

> [!TIP]
> 替代 `K.spotlight` 的锐利等腰三角形边界：在 `core.js` 中使用多步径向渐变叠加的 `drawSoftBeam()` 绘制柔和体积光柱，避免舞台边缘出现生硬几何切线。

## 2. `1080×1440`（`3:4`）与 `1080×1920`（`9:16`）纵向五区防撞排版

竖屏小屏阅读容错极低，必须严格隔离 **HUD、章节大标题、发光主角、引线标注、单行字幕** 五个垂直带：

| 垂直分区 | `3:4` (`1080×1440`) 坐标 | `9:16` (`1080×1920`) 坐标 | 刚性约束 |
| :--- | :--- | :--- | :--- |
| **Band 1：HUD 章节条** | `y ∈ [40, 95]`（仅左上角） | `y ∈ [55, 120]` | **禁用 `K.hud.corner(...)`** 右上角读数，**禁用 `K.ghost(...)`** 巨字底纹，防竖屏顶角杂乱；片名卡与结尾用 `K.hud.show` 控显隐 |
| **Band 2：章节大标题 / 金句** | Hero `y ∈ [132, 220]`；片名 `T` `y ≈ 185`（`146px`）+ 副标题 `y ≈ 372` | Hero `y ∈ [220, 320]`；片名 `y ≈ 280` | 开场 `hook` 建议 `y ≈ 132`（`size: 76–84`）避开下方主体，或与主体上下错峰；转场时优先 `mode: 'rise', blur: 0` |
| **Band 3：发光主角主区** | `y ∈ [420, 820]`；片名卡图腾中心 **`y ≈ 850`** | `y ∈ [520, 1080]`；片名卡 `y ≈ 1080` | 主角占画幅 30%–60%，须在 `core.js` 内手写 **3–5 个细节层级**（体块渐变、功能结构、流动信号、边缘反光），严禁复用方框 UI 卡或火柴人 |
| **Band 4：引线标注安全带** | **`y ∈ [880, 1080]`，`x ∈ [95, 985]`** | **`y ∈ [1150, 1460]`，`x ∈ [95, 985]`** | 每帧最多 `1–2` 处，置于主体外纯黑缓冲区；必须做左右与上下钳位 |
| **Band 5：底部单行字幕** | **`y = H - 150`（约 `1285–1290`）** | **`y ≈ 1620–1680`** | `52px`、绝对单行、无句末标点、`1080px` 宽下金句 `<=12` 字 / 正文 `<=15` 字 |

## 3. 转场糊影、向内反转碰撞与 JS 工程铁律

### 3.1 消除 `mode: 'center'` 的 14px 高斯糊影
`kit.js` 中 `K.text` 的 `mode: 'center'` 写死了 `bl = (1 - k) * 14` 高斯模糊；在 `sweep` / `iris` 转场瞬间会出现一整团模糊重影。
- **正确做法**：所有章节标题与关键文字改用 `mode: 'rise', blur: 0, y: 22`（或 `mode: 'wipe'`），并在 `lightSweep` / `irisWipe` 场景起点后延迟 **`+0.36s`** 再触发 `reveal`，让画面切换干净利落再出字。

### 3.2 防范 `safeCallout` 向内反转压穿主体
当引线锚点靠近右边界（如 `x > 820`）时，朴素 `safeCallout` 若检测到 `x + dx + len + textW > 985` 而自动把 `dx` 翻转成 `-Math.abs(adx)`，标注文字会**直接横穿到画面中央主角身上**！
- **正确做法**：
  1. 优先缩减横线长度 `len` 并向右对齐，或从主角底缘垂直向下拉入专属纯黑区 `y ∈ [880, 1080]`；
  2. 只在明确朝向空白外侧方向时使用自动翻转，且盲审必查 `2_关键帧.png` 确认标注零重叠。

### 3.3 确定性与全局作用域隔离
- **IIFE 封装 `scenes.js`**：所有章节渲染代码必须包裹在 `(function () { 'use strict'; ... })();` 内。
- **`cover.html` 共用 `core.js` 冲突防护**：`index.html` 与 `cover.html` 都会加载 `motion.js` → `kit.js` → `core.js`。`core.js` **严禁顶层 `const TAU` / `const E` 重复声明**，应通过解构别名或直接使用 `M.TAU`、`M.ease`；若需三次/二次贝塞尔工具函数，统一在 `core.js` 内定义 `bezCubic` / `bezQuad`。
- **绝对纯函数时间驱动**：严禁 `Math.random()`（改用 `M.hash` / `M.rng`）、`Date.now()`、`setInterval` 或 CSS `transition`；大改后必过 `verify.mjs --tol 24` 全点零差验证。
- **4K 封面安全区红线**：横版封面（设计 `1920×1080` → 输出 `3840×2160`）所有关键图文与主体必须约束在中央 `4:3` 区域 **`x ∈ [240, 1680]`** 内，并用 `cover.mjs --guides` 生成安全区参考图逐帧眼检。
